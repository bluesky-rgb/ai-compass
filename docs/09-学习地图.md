# 09 学习地图

**学习不再按“看到什么好项目就研究什么”，而是按数据闭环补短板，每一项都落到正在做的项目上。** 当前最该补的是“消化”和“业务”两块。

每一环都回答四个问题：为什么学、要掌握什么、已经研究过什么、下一步练什么。“下一步练什么”都绑定在科研新手助手上，学完马上就能用。

## 获取：让数据自己进来

- **为什么学**：没有持续进来的真实数据，后面一切都是演示。
- **要掌握**：调用公开数据接口（如 Europe PMC、OpenAlex、PubMed）；分页、限速和失败重试；去重和统一格式；定时运行的采集任务。
- **已经研究过**：`paper-research-workbench`（Europe PMC 检索、去重、排序）、`0711_news_codex`（信息源校验和版本管理）、`1013` 里的 Production Agentic RAG（arXiv 论文采集）。
- **下一步练**：为那位学生选定的方向，每周自动拉取一次新论文，生成一份更新清单。

## 消化：把资料变成知识（最弱，优先）

- **为什么学**：AI 的价值在于替人“读懂和记住”，这一环决定产品有没有真本事。
- **要掌握**：PDF 全文和版式解析；表格和图表的数据提取；把长文切块并建立检索（RAG）；知识库和知识图谱；跨会话的长期记忆；回答时能追溯到原文出处。
- **已经研究过**：nativePDF-structurer（`0828`）、PDF Craft（`0916`）、BabelDOC（`0823`）、LLM Wiki（`0829`）、Graphify（`0911`）、Hindsight 长期记忆（`0926`）、Production Agentic RAG（`1013`）。
- **下一步练**：把课题入门包里的 20 篇论文做成一个可以提问的课题知识库，每个回答都标出来自哪篇、哪一页。

## 展示：让人一眼看懂（最强，保持）

- **为什么学**：已经是最强项，不再单独投入，只服务于落地项目。
- **要掌握**：用最简单的形式交付，比如 PDF、清单、对比表，而不是炫技。
- **已经研究过**：大量 3D、图表、视频演示；Diagram Design（`0914`）、Archify（`0909`）。
- **下一步练**：把领域地图里的方向对照做成一页可交互的选择工具。

## 交互：让 AI 替人做事

- **为什么学**：从“回答问题”走向“完成任务”，是工具升级为助手的关键。
- **要掌握**：工具调用和 Agent 执行；多轮对话的上下文管理；根据用户反馈更新知识库。
- **已经研究过**：Pi Agent Harness（`0910`、`0929`）、cmux 多 Agent 工作台（`1013`）、共想室（`expert-decision-room`）、学术研究 Skill（`1025`）。
- **下一步练**：做一个课题助手，用户问“这个方向还有什么没人做”，它基于知识库给出带出处的回答。

## 业务：发现需求、验证价值

- **为什么学**：技术不缺，缺的是知道什么值得做、别人愿不愿意付钱。
- **要掌握**：用户访谈（问过去的行为，不问想法；可参考 Rob Fitzpatrick 的 *The Mom Test*）；需求筛选的四个条件；先人工服务再自动化；小额定价试探；合规边界。
- **已经研究过**：基本空白。
- **下一步练**：和那位研究生做第一次访谈，按 [05 落地线](05-落地线-科研新手助手.md) 里的问题清单记录他的回答。

## 基础设施：让服务一直在线

- **为什么学**：真实业务需要一直运行的后端和安全存放的用户数据。
- **要掌握**：Linux 服务器基础；Docker 部署；数据库；域名和 HTTPS；国内备案流程；定时任务和日志。
- **已经研究过**：WireGuard 自建 VPN（`1013`）、部分仓库的 Docker 和部署配置。
- **下一步练**：落地项目进入阶段 2 时再开始，不提前。

## 学习规则

1. 每研究一个新项目，先问三个问题：补哪一环？能用在落地项目上吗？有真实数据可接吗？
2. 答不出来，只记笔记，不做完整演示。
3. 学完一项，在这里把它从“要掌握”移到“已经研究过”，并写下用在了哪里。
