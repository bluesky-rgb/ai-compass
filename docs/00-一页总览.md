# 00 一页总览

*截至 2026-10-31。只有一页，忘了方向时先读这里。*

## 核心

**以产品和能力构建为核心：用真实场景打磨产品，在产品里长出能力，收入从产品和能力中来。** IP 是把这个过程公开出去的方式。

## 我是谁，现在在哪

- 2026 年 7～10 月：95 个公开仓库、约 650 项研究、400 多个演示，研究过约 500 个开源项目
- 现在：全职推进，储备约够 3 个月生活

## 核心判断

1. **AI 是工具，数据是原料，真实场景决定价值。**
2. 人处理信息分四步：获取、消化、展示、交互。我展示最强，消化最弱，真实数据空白。
3. AI 让执行变便宜，人的价值在于发现问题、判断取舍、连接真实世界、为结果负责。
4. 单纯用 AI 做 3D 产品，真实场景价值不够，不作主线。

## 三条线

| 线 | 是什么 | 现在做什么 |
| --- | --- | --- |
| **落地线（产品）** | 用真实场景打磨产品，验证价值并带来收入 | 科研新手助手：把领域地图交给研究生，人工做第一份课题入门包；同时用已有作品承接定制需求，作为真实客户和收入 |
| **能力线** | 按数据闭环补短板，建可复用的底座 | 补“消化”：课题知识库、文档解析；只学能用在产品和订单上的东西 |
| IP 线 | 公开记录从探索走向产品 | X 重新定位，发置顶串推，每周至少 3 条 |

## 跑道约束

储备约 3 个月，所以给产品和能力设三个检查点。求职是保底，只在检查点没达到时启动，详见 [13 跑道约束与保底](13-三个月跑道计划.md)。

| 时间 | 看什么 |
| --- | --- |
| 约 2026-11-28 | 产品或定制服务有没有第一笔收入或明确付费意向 |
| 约 2026-12-26 | 收入能不能覆盖一部分生活开支 |
| 约 2027-01-23 | 跑道见底前必须有收入来源 |

## 四条原则

1. **先人工，后自动**：用户反复用到的部分才写成代码。
2. **每个阶段有过关条件**：没达到就不进入下一阶段，避免停在 80%。
3. **研究先问三个问题**：补哪一环？能用在产品上吗？有真实数据吗？并记录“能力前后”。
4. **公开失败**：放弃的方向和失败案例照样写出来。
